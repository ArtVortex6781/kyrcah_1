# TicTacToe GA — нейроэволюция агента для крестиков-ноликов

Учебный эксперимент по обучению игрового агента для классических крестиков-ноликов **3 × 3** с помощью генетического алгоритма (**GA**) и нейронной сети на **Keras**.

## Возможности проекта

- Игровая среда TicTacToe, партии против случайного соперника или другой нейросети.
- Нейросеть `GRU(64) → Dense(9, softmax)`, выбирающая клетку игрового поля.
- Генетическая оптимизация весов с использованием **DEAP** и сохранением элитных особей (`HallOfFame`).
- Сохранение параметров запусков и статистики поколений в локальную **SQLite**.
- Графики динамики приспособленности (*fitness*) и сохранение моделей в формате `.keras`.
- Консольная игра против сохранённой модели.

## Как устроен эксперимент

```text
Начальная популяция хромосом (веса GRU + Dense)
        ↓
Оценка fitness по партиям TicTacToe
        ↓
Tournament selection → crossover → mutation
        ↓
Элитизм и переход к следующему поколению
        ↓
Статистика поколений в SQLite
        ↓
Выбор лучшего индивидуума → сохранение .keras
```

Одна особь кодирует **13 833 параметра** нейросети. Код использует tournament selection, simulated binary crossover, polynomial bounded mutation и элитизм. В текущем `gen_alg.py` задано 42 особи, 39 поколений и оценка по 5 партиям на особь.

Для отображения поля используются значения `45` (пустая клетка), `2` и `3` (игроки); сеть получает матрицу `3 × 3`, а выходной слой формирует девять оценок возможных ходов.

**Особенность функции fitness:** ход на занятую клетку штрафуется, после чего в оценочных партиях вместо него выполняется случайный допустимый ход. Поэтому итоговые победы не следует интерпретировать как качество только прямых предсказаний сети. Эта особенность сохранена как часть исходного эксперимента.

## Структура репозитория

| Файл / каталог | Назначение |
|---|---|
| `gen_alg.py` | Настройка и запуск генетического алгоритма, логирование и сохранение результата |
| `algelitism.py` | Модификация эволюционного цикла DEAP с элитизмом |
| `ns_keras.py` | Определение нейросети и преобразование хромосомы в веса |
| `classes_for_game.py` | Логика игры, оценочные партии и интерактивная игра |
| `logs.py` | Работа с SQLite, параметры и статистика экспериментов |
| `draw_plots.py` | Построение графиков по сохранённым данным |
| `test_model.py` | Консольная партия против модели |
| `models/` | Сохранённые модели `.keras` |
| `plots/` | Графики результатов эксперимента |
| `database_logs/` | Локальная база логирования (не распространяется с репозиторием) |

## Требования

- Python 3.12.
- Зависимости из `requirements.txt`: NumPy, DEAP, Keras, TensorFlow и Matplotlib.
- Для интерактивных графиков используется Matplotlib backend `TkAgg` (нужна поддержка Tk и графический сеанс).

Установка зависимостей:

```bash
python -m pip install -r requirements.txt
```

## Игра против сохранённой модели

В репозитории оставлена модель `models/modelv7_5igr.keras`. Для запуска интерактивной партии:

```bash
python test_model.py
```

Нейросеть ходит первой, после чего программа ожидает координаты хода человека в формате `строка столбец`, с индексами от `0` до `2`, например `1 2`.

Запуск возможен из любого рабочего каталога: пути к моделям теперь вычисляются относительно расположения Python-файлов.

## Генетическое обучение

```bash
python gen_alg.py
```

Текущая конфигурация использует `modelv7_5igr.keras` как соперника оцениваемой сети и сохраняет новый результат в `models/modelv9_5igr.keras`. Это **новый эксперимент**, а не воспроизведение исходного обучения модели v7.

Перед первым запуском обучения на чистой копии репозитория необходимо создать таблицы SQLite (сама папка и файл БД создаются автоматически):

```python
from logs import WorkWithDB, ResetTables

with WorkWithDB() as db:
    ResetTables.reset_all_tables(db)
```

**Внимание:** `reset_all_tables()` удаляет существующие таблицы и их содержимое. Используйте его только для новой пустой БД, не для сохранённой истории экспериментов. Если база уже подготовлена, инициализацию повторять не нужно.

Полноценное обучение вычислительно затратнее простой демонстрации модели. Для просмотра результата достаточно `test_model.py`.

## Результаты и графики

В проекте сохранены графики отдельных запусков, отражающие максимум, среднее, минимум и разброс fitness по поколениям:

- [Динамика fitness](plots/fitness_trend_run17.png)
- [Стандартное отклонение fitness](plots/fitness_std_run17.png)

Графики создаются функциями `fitness_trend_run17()` и `fitness_std_run17()` из `draw_plots.py`, которым необходимы соответствующие записи в локальной SQLite-БД. Номер запуска в именах файлов — историческое обозначение: выборка в коде производится по `gen_id=16`.

Модель не является оптимальной стратегией для крестиков-ноликов. На результат влияют fitness, ограниченная выборка партий и обработка недопустимых ходов. Проект демонстрирует построение и анализ нейроэволюционного эксперимента, а не достижение идеальной игры.
